# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Sevens (Fan Tan): an online multiplayer card game. The whole app is two files with **no dependencies**: `server.js` (Node ≥18 built-ins only: `http`, `fs`, `path`, `crypto`, `zlib`) and `index.html` (all client HTML/CSS/JS inline). There is no build step, linter, or test suite.

## Commands

- Run: `npm start` (or `node server.js`), then open http://localhost:3000
- Health check: `GET /health` → `ok`
- `index.html` is read once at startup (`INDEX_HTML`), so **restart the server after editing it**.

Env vars (all optional): `PORT` (3000), `PUBLIC_ORIGIN` (needed for the lobby's share link `/?r=CODE`; blank hides it), `GRACE_MS` (30000, reconnect window before a bot takes over), `DEBOUNCE_MS` (1500), `JOIN_WAIT_MS` (20000), `INVALID_WAIT_MS` (5000), `PASS_MS` (5000, how long a connected player with no playable card has to press Pass before it happens for them; a hidden tab passes at once, and a player who drops mid-countdown is passed after 1.2s), `TURN_WAIT_MS` (10000, how long the table waits on a disconnected player's turn before a bot makes that one move; they keep their seat), `BOT_MS` (50, bot think budget per move; 8 on Render), `BOT_SHARE_MS` (300, total bot think time allowed per second across all tables; 40 on Render, whose 0.1-CPU quota freezes the whole process once spent), `TRUST_PROXY` (0; number of trusted reverse-proxy hops. **Set it to 1 behind a proxy/PaaS**, otherwise every visitor shares one rate-limit bucket; leave 0 when exposed directly, or clients could spoof `X-Forwarded-For`), `CLIENT_IP_HEADER` (a header the edge proxy overwrites with the visitor's address, e.g. `cf-connecting-ip`; read before `X-Forwarded-For`; rate limiting only), `VOICE_TTL_MS` (600000, how long a voice note is kept), `VOICE_TOTAL_MAX` (32 MB, all voice notes in memory across tables; oldest dropped first), `FORCE_HTTPS` (`1` 301-redirects requests whose `X-Forwarded-Proto` is `http` to `PUBLIC_ORIGIN`; on by default when `PUBLIC_ORIGIN` is https and `TRUST_PROXY` is set).

**Hosting on Render (free tier):** the server detects Render (`RENDER=true`) and defaults `PUBLIC_ORIGIN` to `RENDER_EXTERNAL_URL`, `TRUST_PROXY` to 1 and `CLIENT_IP_HEADER` to `cf-connecting-ip` (Render sits behind Cloudflare), which turns on HSTS and the http→https redirect, and lowers the bot think budgets; explicit env vars still win. The startup log prints what was detected, and the server warns (at most once a minute) when the event loop stalls over 200ms. Free services sleep after 15 minutes without *incoming* requests and lose all tables (state is in memory); because SSE only carries traffic outward, a seated client pings `GET /health` every 5 minutes while its user has been active in the last 30. Set Render's health check path to `/health`.

`server.js` exports internals (`botChoose`, `heurChoose`, `evalMove`, `handPts`, `hasFourKings`, `canFinishInThree`, `createAppServer`, `rooms`, `byToken`, …) and only listens when run directly (`require.main === module`), so it can be `require`d from an ad-hoc script to exercise logic. Rooms also honor `S.forceDeck` (a 52-card array used for the next deal) and `S.invalidWaitMs` for deterministic testing.

## Releases and rollback

Each working release on `main` is tagged `vX.Y` (`git tag -n` lists them with a one-line summary): v1.0 Table talk, v1.1 UI refresh / equal deal / hardening, v1.2 instant Open table, v1.3 Pass button, v1.4 voice chat, v1.5 reload fix / Render setup / 5s pass, v1.6 voice chat removed, v1.7 rejoin fix / per-round results / End game, v1.8 gameplay fixes (deal keeps briefly-offline players, 10s wait on an absent player, per-seat rate limits, set-aside made visible), v1.9 late-join points / no set-aside chat line / state versions / low-end phone performance, v1.10 instant (optimistic) moves, v1.11 quick phrases / voice notes / table themes / haptics (removed in v1.16), v1.12 bolder themes / iPhone address-bar layout fix, v1.13 animated themes (Galaxy, Neon night, Ocean) / banter phrases + your own line / coloured bubbles / Brave layout hardening, v1.14 animations on phones + Animations switch / Hindi banter / editable 8th phrase, v1.15 seven fixed phrases + an empty own-line slot, v1.16 vibration removed / phrase button fixed on the felt's rim / own line capped at 26 / invite-link hosting fix. Tag each new release the same way. To roll production back without rewriting history: `git revert --no-edit <tag>..HEAD` then push (Render redeploys from `main`), or use the Rollback button on a past deploy in Render's dashboard.

**Voice chat was tried and removed (v1.6).** Voice *notes* (v1.11) are different and safe: recorded clips uploaded once through this server, so no peer connections. It was a peer-to-peer WebRTC mesh signalled through this server (code at tags v1.4/v1.5). Without a TURN relay it failed between players on mobile data (carrier-grade NAT), which is how most people play, and no reliable free relay exists, so it was dropped. Don't reintroduce it without a funded TURN relay.

## Architecture

**Transport:** client → server is `POST /api` with a JSON body `{ a: <action>, t: <token>, ... }`; server → client is Server-Sent Events on `GET /events?t=<token>`. There are no WebSockets. Actions in `act()`: `join`, `start`, `play`, `pass`, `chat`, `leave`, `skipwait`, `resetscores`, `endgame`, `newgame`. `/api` enforces JSON content-type, same-origin `Origin`, a 2000-byte body cap, and rate limits: per seat (token) for game actions (`SEAT_MAX`, 60/10s) and per address only as a flood guard (`IP_FLOOD_MAX`, 300/10s), because a whole table often shares one Wi-Fi or carrier address. The client retries once on HTTP 429, and `recoverSeat()` treats it as transient; strict CSP headers mean the client must not load external resources. The CSP allows only the page's single inline `<script>`, pinned by a SHA-256 hash computed at startup, so **inline event-handler attributes (`onclick="…"`) and extra inline scripts will not run**; use `addEventListener`. `index.html` is served pre-compressed (brotli/gzip) with an ETag.

**State is all in memory** (lost on restart): `rooms` (code → table `S`), `byToken` (token → `{S, p}`), `conns` (token → set of SSE responses). Each mutation ends in `push(S)`, which bumps the state version `S.ver` (sent as `v`; the client drops any state older than the one it has, because an `/api` reply can reach a phone after newer pushes and would otherwise rewind it to an old turn) and sends every player their own `view(S, p)` (= private `ownView` + shared `commonView`, the latter serialised once per push) (other players' hands are hidden; only counts, plus `leftCards` once the phase is `over`). `push()` also drives the game loop: it schedules auto-passes when the current player has no legal move, and bot moves for disconnected players.

**Card encoding:** `id = suit*13 + (rank-1)`, suits `♠♥♦♣`; 7♥ = 19 (`H7`) must open each round. `board[suit]` is `null` or `[lowRank, highRank]`. Card points = rank (A=1 … K=13); a round's score is the points left in hand (lower is better).

**Equal deal:** every player gets the same number of cards. When 52 does not divide by the player count, `removedFor(n)` sets aside the lowest cards one suit at a time (A♠ A♥ A♦ A♣, then 2♠ …; at most 8, for 11 players). They are in `S.removed`, sent to clients as `removed` (no chat line; the client toasts them at each fresh deal, leads the player strip with a "Not in play" chip, and marks each affected suit row, gold once that end of the run is complete), and must be treated as held by nobody (the bot does this through `GONE`). The client has its own copy of `removedFor` for the lobby preview.

**Table phases:** `lobby` → `playing` → `over` (→ next round, or `final`), plus `invalid` (when a deal gives one player all 4 Kings: the round is voided and the host must wait `INVALID_WAIT` before redealing). The host is the first connected player (`hostId`). Players who join mid-round become spectators. `finishRound()` appends each round to `S.history` (`{round, rows:[{id,name,pts,place}]}`, kept by id and name so players who leave still count). The `over` screen shows only that round (round winner, cards left, points this round). The host's `endgame` moves to `final`, the only phase whose view includes `history`; the client derives totals with `finalStandings()` (lowest total wins, ties to more round wins), and the share poster is offered only there. Both results cards share one layout (`scHero` winner summary + a ranked `.res-item` list, one line per row; leftover cards capped at six plus a "+N" chip). There is deliberately no round-by-round table, which broke past ~10 rounds: each final row is a button that reveals that player's rounds as wrapping chips, and open rows are remembered in `resOpen` across re-renders. `newgame` (host, from `final`) zeroes scores, history and join points and returns to the lobby. **Late joiners:** lowest total wins, so a player dealt in for the first time after round 1 starts at 90% of the highest running total among seated players (`applyJoinPoints` in `start()`, after the four-Kings check, so a void deal doesn't apply it; recorded in `S.joins`, sent only in `final`, added by `finalStandings()` and shown as a "Joined Rn" chip). Running totals are deliberately not shown during play: player chips show cards only.

**Disconnect/rejoin:** a dropped SSE connection starts a `GRACE` timer (`p.deadline`); after that `p.bot = true` and the bot plays for them. Rejoining matches a player by `cid` and/or name, issues a new token, and drops the bot. `cid` is one id per **browser** (localStorage `sevensCid`), so a seat with the same `cid` is reclaimed even if it still looks connected (a second tab, or a stream the proxy has not closed yet); its old streams get `event: replaced` and that page steps aside instead of fighting for the seat. Without a `cid` match only a disconnected seat with the same name is reclaimed, so a different browser using a connected name becomes "Name 2". The many per-player timers (`dtimer`, `btimer`) and `S.timer`/`S.idle` must be cleared when state changes. Use `forgetPlayer()` to remove a player, because it keeps the `S.turn` index valid. `start()` deals in seated players who are only briefly offline (phones drop the stream whenever the screen locks) and puts them on the same grace via `startGrace()`; it removes only players who left or never connected. On an absent player's turn the table waits `TURN_WAIT` (`awayDue`, one deadline per turn), then the bot makes that single move. Client side, an EventSource that closes for good (`readyState 2`) does **not** mean the seat is gone: Chrome also closes it while a page reloads, before `pagehide`. `recoverSeat()` waits briefly (timers never fire on an unloaded page), then sends `join` with the old token plus room, name and `cid`; only if that fails does `forgetSeat()` clear the stored token. If the server says the table no longer exists, the `?r=` code is removed from the address too; and `join()` takes the room only from the code box (clearing it means "open a new table", even on a page opened from an invite link) and clears the address before joining, because `applyIncomingState` sends the player home when the address names a different table than the one they are in. A server that is unreachable (`offline`) is retried with backoff.

**Bot (`botChoose`):** determinization Monte Carlo. It samples the hidden hands consistent with known voids (`p.void`, filled in by `recordPass`), runs heuristic rollouts (`heurPick`/`evalMove`) per candidate move within `BOT_MS`, and falls back to `heurChoose`.

**Table extras (v1.11):** everything rides on `/api` + SSE, nothing peer-to-peer.
- *Quick phrases:* `{a:'chat', phrase:i}` picks from `PHRASES` (same list in both files; by index so it can't carry other text; 2s per seat). `PHRASES` holds the seven fixed phrases; the 8th tray slot is the player's own line, empty ("Your line" with a pencil) until they write one (`sevensMyLine` on the phone; sent as `{a:'chat', custom}`, cleaned like chat, at most 26 characters (the longest fixed phrase, so a bubble shows it whole), same 2s gap). Seat bubbles take the sender's avatar hue (`nameHue`) and stack when neighbours' would overlap. Player chat entries carry `pid` (sender id) and `kind` (`''`, `'phrase'`, `'voice'`).
- *Voice notes:* `POST /voice?t=&d=<ms>` with the raw clip (audio/mp4|webm|ogg|aac|mpeg, magic bytes checked, ≤160 KB, 0.5–8.5s, one per 3s and 10/min per seat; same-origin). Stored in `S.voices` (last 15 per table, `VOICE_TTL`, global `VOICE_TOTAL_MAX`, freed in `dropRoom`, swept on the 15s heartbeat), announced as a chat entry `{kind:'voice', vid, dur}`. `GET /voice/<vid>?t=` serves it only to a token at the same table, with byte ranges (Safari needs them). Audio never travels inside game state. `Permissions-Policy` allows `microphone=(self)`.
- *Client:* a 💬 button (`#qBtn`, outside `#app` so table redraws don't rebuild it; `placeFab()` pins it to the felt's bottom-right rim after every layout, mostly outside the felt so a full felt never hides it; only while playing) opens the tray (`#qTray`: phrases + Voice note). Recording is tap to start / tap to send (`startRec`/`stopRec`/`finishRec`); the clock starts on the recorder's `start` event because phone encoders can take ~1s. Seat bubbles (`showBubble`/`placeBubbles`, layer `#bubbles` outside `#app`) come from `bubbleNew()` in `paintChat()` for messages new since the last paint, never for history or a backlog after the screen was off (`resumedAt`), and never cause a `render()`. Popovers (`#qTray`, `#setPop`) swallow the outside tap that closes them (capture `pointerdown` + `swallowUntil`), so it can't play a card.
- *Settings:* `#setBtn` in the top bar: felt (`html[data-felt]` overrides every surface token: `--felt-*`, `--sc-*`, `--glow`, `--bg*`, the panel/chat/toast/glass rgb triplets `--ui-1`/`--ui-2`/`--toast-rgb`/`--ink-rgb`, and `--poster-*` for the shared scorecard image; never hard-code a surface colour, add a token; `sevensFelt`) (themes: Classic green, Galaxy, Neon night, Ocean; v1.12's blue/wine/charcoal map onto the new ones), animated layers (`fxHTML`) on the felt (`.fx`, rebuilt with every table render, so each piece gets a negative `animation-delay` from `Date.now()` and keeps moving seamlessly; keep felt pieces few and cheap, e.g. star fields are painted gradients) and on the page backdrop (`#fxBg` in `#lpBg`, persistent); hidden by `html.nofx` (the player's Animations switch, `sevensFx`, or for the session when a phone is measured slow; deliberately *not* tied to `html.lite`, whose device hints such as 4 reported cores catch most phones) and stopped by reduced motion. Below 440px the brand word hides so the top bar fits.

**Special announcements:** `maybeLastThree` posts a chat alert when a player's last 3 cards are guaranteed to finish (`canFinishInThree` brute-forces the 6 orderings).

**Client (`index.html`):** a single `<script>` with global state `G` (the latest server view) and full re-render functions (`render`, `lobby`, `table`, `buildRoundOverModal`, …). Passing: with no playable card the player sees a Pass button; the deadline (`passDue`, one per turn via `S.turnSeq`) survives re-pushes, and `ownView` sends the ms left as `pass`. The hand keeps natural stacking order so every card stays readable; playable cards are lifted and outlined in gold, not brought forward. It also contains a fully **offline practice mode** (`startPractice`, `pPlay`, `P_STATE`, `pCanFinishInThree`, `pEvalBotMove`) that **duplicates the server's game rules on the client**, so rule changes usually have to be made in both places. All colours, fonts and easing live in the `:root` design tokens at the top of the `<style>` block (use `var(--gold-2)`, `rgba(var(--gold-rgb),.3)`, `var(--sans)`/`var(--serif)` rather than new literals; the CSP rules out web fonts, so type is system stacks only). **Performance on low-end phones matters** (most players are on phones): cards size themselves from `--u` (1% of `--w`), not `cqw`, because a size container per card made each layout cost about 1s at 6× CPU throttle; suit shapes are inline SVG paths (`SUIT_PATH`), not `<use>`; `fit()` reads all sizes before writing; pulsing glows animate the opacity of a pseudo-element, never `box-shadow`. **Viewport on iPhones:** the keyboard and Safari's address bar shrink `innerHeight` but not the page, and Safari often sends no resize when they close, so portrait vs landscape comes from `viewWide()` (the page's own `documentElement` size), never `innerWidth/innerHeight`. `settleView()` (on visualViewport resize, focusout, pageshow, returning to the tab) scrolls back anything Safari left scrolled and re-fits the table if its size changed; the viewport meta has `minimum-scale=1` so a momentary overflow can't leave the page zoomed out, and `interactive-widget=resizes-visual` so Chromium browsers (Chrome, Brave on Android) don't resize the page for the keyboard. `settleView` checks three times (toolbars animate) and re-applies the viewport meta if the page was left zoomed. Open the game with `?vd=1` to show a readout of the sizes the layout uses, for diagnosing a phone that lays out wrongly. When only presence (`on`/`bot`) changes, `applyIncomingState` repaints just the player strip (`coreSig`). Redraws wait while a finger is on the hand (`requestRender`, up to 1.5s), since replacing the card under a finger swallows the tap. **Moves never wait for the server** (a round trip to Render from a phone is often 0.5-2s): a card is played on `pointerup` (the click that follows is ignored; it arrives 100-350ms later on phones), and `sendMove()` shows the predicted state at once (`predictMove`: card to the felt, turn to the next seat still in the round, the same order as the server's `advance()`), with one move in flight (`pred`). Incoming states that predate the move (`predates()`, e.g. someone's connection flickered) are re-predicted instead of undoing it; any other state confirms it (`settle`). A refusal, being offline, or 8s without confirmation calls `rollback()`, which restores the last real state with a toast. Pass works the same way. Practice mode is local and skips all this. Keep new interactions instant in the same way. `html.lite` (few cores, little memory, or three renders over 120ms, remembered in `sevensLite`) drops backdrop blur and the felt grain. Because the table is re-rendered from scratch on every state, table motion is FLIP-style: `snapTable()` measures the old DOM and `animateTable()` animates the new one (card flight to the felt, hand reflow, deal-in). The victory scorecard is drawn on a canvas (`generateScorecardCanvas`) and shared through the Web Share API or downloaded.
