# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Sevens (Fan Tan): an online multiplayer card game. The whole app is two files with **no dependencies**: `server.js` (Node ≥18 built-ins only: `http`, `fs`, `path`, `crypto`, `zlib`) and `index.html` (all client HTML/CSS/JS inline). There is no build step, linter, or test suite.

## Commands

- Run: `npm start` (or `node server.js`), then open http://localhost:3000
- Health check: `GET /health` → `ok`
- `index.html` is read once at startup (`INDEX_HTML`), so **restart the server after editing it**.

Env vars (all optional): `PORT` (3000), `PUBLIC_ORIGIN` (needed for the lobby's share link `/?r=CODE`; blank hides it), `GRACE_MS` (30000, reconnect window before a bot takes over), `DEBOUNCE_MS` (1500), `JOIN_WAIT_MS` (20000), `INVALID_WAIT_MS` (5000), `PASS_MS` (5000, how long a connected player with no playable card has to press Pass before it happens for them), `BOT_MS` (50, bot think budget per move), `BOT_SHARE_MS` (300, total bot think time allowed per second across all tables), `TRUST_PROXY` (0; number of trusted reverse-proxy hops. **Set it to 1 behind a proxy/PaaS**, otherwise every visitor shares one rate-limit bucket; leave 0 when exposed directly, or clients could spoof `X-Forwarded-For`), `CLIENT_IP_HEADER` (a header the edge proxy overwrites with the visitor's address, e.g. `cf-connecting-ip`; read before `X-Forwarded-For`; rate limiting only), `FORCE_HTTPS` (`1` 301-redirects requests whose `X-Forwarded-Proto` is `http` to `PUBLIC_ORIGIN`; on by default when `PUBLIC_ORIGIN` is https and `TRUST_PROXY` is set). Voice chat: `STUN_URLS` (comma list; defaults to Google's and Cloudflare's free public STUN; set empty for none), `TURN_URLS` plus either `TURN_SECRET` (coturn `use-auth-secret`; each player gets a 12-hour HMAC credential) or `TURN_USER`/`TURN_PASS` (static, visible to players), and/or `CF_TURN_KEY_ID` + `CF_TURN_API_TOKEN` (Cloudflare's hosted TURN: the server fetches 6-hour credentials from `rtc.live.cloudflare.com` at startup and hourly, drops port-53 URLs, and shares them with players who join voice). Without TURN, players on strict networks (some offices, mobile carriers) can see the table but not hear each other.

**Hosting on Render (free tier):** the server detects Render (`RENDER=true`) and defaults `PUBLIC_ORIGIN` to `RENDER_EXTERNAL_URL`, `TRUST_PROXY` to 1 and `CLIENT_IP_HEADER` to `cf-connecting-ip` (Render sits behind Cloudflare), which turns on HSTS and the http→https redirect; explicit env vars still win. The startup log prints what was detected. Free services sleep after 15 minutes without *incoming* requests and lose all tables (state is in memory); because SSE only carries traffic outward, a seated client pings `GET /health` every 5 minutes while its user has been active in the last 30. Set Render's health check path to `/health`.

`server.js` exports internals (`botChoose`, `heurChoose`, `evalMove`, `handPts`, `hasFourKings`, `canFinishInThree`, `createAppServer`, `rooms`, `byToken`, …) and only listens when run directly (`require.main === module`), so it can be `require`d from an ad-hoc script to exercise logic. Rooms also honor `S.forceDeck` (a 52-card array used for the next deal) and `S.invalidWaitMs` for deterministic testing.

## Releases and rollback

Each working release on `main` is tagged `vX.Y` (`git tag -n` lists them with a one-line summary): v1.0 Table talk, v1.1 UI refresh / equal deal / hardening, v1.2 instant Open table, v1.3 Pass button, v1.4 voice chat, v1.5 reload fix / Render setup / 5s pass. Tag each new release the same way. To roll production back without rewriting history: `git revert --no-edit <tag>..HEAD` then push (Render redeploys from `main`), or use the Rollback button on a past deploy in Render's dashboard. Voice runs on free public STUN only, with no TURN relay configured, by choice.

## Architecture

**Transport:** client → server is `POST /api` with a JSON body `{ a: <action>, t: <token>, ... }`; server → client is Server-Sent Events on `GET /events?t=<token>`. There are no WebSockets. Actions in `act()`: `join`, `start`, `play`, `pass`, `chat`, `leave`, `skipwait`, `resetscores`, `voice`; plus `sig`, which is only accepted on `POST /rtc` (16 KB cap, its own rate bucket) and never on `/api`. `/api` enforces JSON content-type, same-origin `Origin`, a 2000-byte body cap, and per-IP rate limits; strict CSP headers mean the client must not load external resources. The CSP allows only the page's single inline `<script>`, pinned by a SHA-256 hash computed at startup, so **inline event-handler attributes (`onclick="…"`) and extra inline scripts will not run**; use `addEventListener`. `index.html` is served pre-compressed (brotli/gzip) with an ETag.

**State is all in memory** (lost on restart): `rooms` (code → table `S`), `byToken` (token → `{S, p}`), `conns` (token → set of SSE responses). Each mutation ends in `push(S)`, which sends every player their own `view(S, p)` (= private `ownView` + shared `commonView`, the latter serialised once per push) (other players' hands are hidden; only counts, plus `leftCards` once the phase is `over`). `push()` also drives the game loop: it schedules auto-passes when the current player has no legal move, and bot moves for disconnected players.

**Card encoding:** `id = suit*13 + (rank-1)`, suits `♠♥♦♣`; 7♥ = 19 (`H7`) must open each round. `board[suit]` is `null` or `[lowRank, highRank]`. Card points = rank (A=1 … K=13); a round's score is the points left in hand (lower is better).

**Equal deal:** every player gets the same number of cards. When 52 does not divide by the player count, `removedFor(n)` sets aside the lowest cards one suit at a time (A♠ A♥ A♦ A♣, then 2♠ …; at most 8, for 11 players). They are in `S.removed`, sent to clients as `removed`, and must be treated as held by nobody (the bot does this through `GONE`). The client has its own copy of `removedFor` for the lobby preview.

**Table phases:** `lobby` → `playing` → `over`, plus `invalid` (when a deal gives one player all 4 Kings: the round is voided and the host must wait `INVALID_WAIT` before redealing). The host is the first connected player (`hostId`). Players who join mid-round become spectators.

**Disconnect/rejoin:** a dropped SSE connection starts a `GRACE` timer (`p.deadline`); after that `p.bot = true` and the bot plays for them. Rejoining matches a player by `cid` (a client id kept in localStorage) and/or name, issues a new token, and drops the bot. The many per-player timers (`dtimer`, `btimer`) and `S.timer`/`S.idle` must be cleared when state changes. Use `forgetPlayer()` to remove a player, because it keeps the `S.turn` index valid. Client side, an EventSource that closes for good (`readyState 2`) does **not** mean the seat is gone: Chrome also closes it while a page reloads, before `pagehide`. `recoverSeat()` waits briefly (timers never fire on an unloaded page), then sends `join` with the old token plus room, name and `cid`; only if that fails does `forgetSeat()` clear the stored token. A server that is unreachable (`offline`) is retried with backoff.

**Bot (`botChoose`):** determinization Monte Carlo. It samples the hidden hands consistent with known voids (`p.void`, filled in by `recordPass`), runs heuristic rollouts (`heurPick`/`evalMove`) per candidate move within `BOT_MS`, and falls back to `heurChoose`.

**Voice chat:** a peer-to-peer WebRTC mesh; no audio touches the server. `voice` sets `p.voice`/`p.vmute` and returns the ICE servers. `players[].voice` in the view is a session number (`p.vs`, bumped when a player joins voice or reconnects; 0 when out of voice or disconnected), and clients key each connection by both ends' sessions, so a change rebuilds it. `signal()` relays one offer/answer to one player as an SSE `event: sig`, storing nothing. Client side (`V`, `voiceSync`, `callPeer`, `onSignal`): the lower player id makes the offer, ICE is gathered before sending (no trickle), so a pair needs one round trip. A reloaded page with no mic open turns its stale server flag off. Practice mode has no voice. `Permissions-Policy` allows `microphone=(self)`; the mic needs https (or localhost).

**Special announcements:** `maybeLastThree` posts a chat alert when a player's last 3 cards are guaranteed to finish (`canFinishInThree` brute-forces the 6 orderings).

**Client (`index.html`):** a single `<script>` with global state `G` (the latest server view) and full re-render functions (`render`, `lobby`, `table`, `buildRoundOverModal`, …). Passing: with no playable card the player sees a Pass button; the deadline (`passDue`, one per turn via `S.turnSeq`) survives re-pushes, and `ownView` sends the ms left as `pass`. The hand keeps natural stacking order so every card stays readable; playable cards are lifted and outlined in gold, not brought forward. It also contains a fully **offline practice mode** (`startPractice`, `pPlay`, `P_STATE`, `pCanFinishInThree`, `pEvalBotMove`) that **duplicates the server's game rules on the client**, so rule changes usually have to be made in both places. All colours, fonts and easing live in the `:root` design tokens at the top of the `<style>` block (use `var(--gold-2)`, `rgba(var(--gold-rgb),.3)`, `var(--sans)`/`var(--serif)` rather than new literals; the CSP rules out web fonts, so type is system stacks only). Because the table is re-rendered from scratch on every state, table motion is FLIP-style: `snapTable()` measures the old DOM and `animateTable()` animates the new one (card flight to the felt, hand reflow, deal-in). The victory scorecard is drawn on a canvas (`generateScorecardCanvas`) and shared through the Web Share API or downloaded.
